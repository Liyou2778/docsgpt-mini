# SQLite 事务与索引

SQLite 是一个嵌入式关系数据库，整个数据库就是一个文件，不需要单独的服务器进程。它适合桌面应用、小型服务和原型系统，部署时只需要 Python 标准库中的 sqlite3 模块。

## 事务与原子性

SQLite 默认开启自动提交模式，每条语句执行完就提交。显式事务用 BEGIN 开始，用 COMMIT 提交，用 ROLLBACK 回滚。把一批相关写操作放进同一个事务，可以保证要么全部成功，要么全部失败，不会留下只写了一半的中间状态。例如替换一个文档的全部分块时，先删除旧分块再批量插入新分块，这两步必须在一个事务里完成。

## WAL 模式与并发

WAL 是 Write-Ahead Logging 的缩写，日志先行模式。开启 WAL 后，写操作先追加到独立的日志文件，读操作可以继续读取旧快照，因此读写不再互相阻塞。对于「后台线程写、请求线程读」这种典型架构，WAL 能显著减少 database is locked 错误。开启方式是对连接执行 PRAGMA journal_mode = WAL；建议同时设置 busy_timeout，让并发写等待而不是立刻报错。

## 索引

索引能加速 WHERE 条件过滤和排序。给经常作为查询条件的列建索引，例如文档状态、分块所属文档的 id。索引不是越多越好：每个索引都会增加写入开销和存储空间，写多读少的表要谨慎。可以用 EXPLAIN QUERY PLAN 查看查询是否用上了索引。

## 参数化查询

所有用户输入都应该通过参数占位符传入，例如 execute 的第二个参数，不要把字符串拼进 SQL。参数化查询既能避免 SQL 注入，也能让 SQLite 复用执行计划。字符串拼接 SQL 在拼接标题、文件名这类外部输入时尤其危险。

## 连接管理

sqlite3 的连接不是线程安全的，跨线程共享一个连接容易出问题。简单可靠的做法是每次操作新建连接、用完关闭，配合 WAL 与超时设置；连接池则适合更高并发的场景。
