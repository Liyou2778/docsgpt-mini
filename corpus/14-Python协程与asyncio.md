# Python 协程与 asyncio

asyncio 是 Python 标准库的异步 IO 框架，核心思想是单线程内通过事件循环并发处理大量 IO 等待，而不是为每个任务开一个线程。

## 协程

用 async def 定义的函数是协程函数，调用它会返回一个协程对象，不会立即执行。协程需要被事件循环调度才真正运行。在协程内部用 await 等待另一个协程或可等待对象，await 期间事件循环可以切换到其他任务，从而在等待网络返回的同时处理其他请求。

## 事件循环

事件循环负责调度所有协程和回调。它维护一个任务队列，不断取出就绪的任务执行，遇到 await 挂起时把控制权交回循环。一个线程同一时刻只能运行一个事件循环，因此不要在协程里执行 CPU 密集或阻塞式操作，例如大量计算、time.sleep、同步的文件读写，这些会卡住整个循环，让所有并发任务一起变慢。

## 并发执行任务

asyncio.gather 可以同时启动多个协程并等待它们全部完成，asyncio.create_task 可以把协程包装成任务在后台运行，asyncio.wait 可以按完成顺序或条件等待。要注意 task 必须被等待或取消，否则异常可能被吞掉。超时控制用 asyncio.wait_for 或 asyncio.timeout 上下文管理器。

## 与线程的关系

asyncio 适合 IO 密集型场景：网络请求、数据库访问、文件读写。CPU 密集型任务应使用多进程或线程池，通过 asyncio.to_thread 可以把阻塞函数放到线程池里执行，避免阻塞事件循环。FastAPI 中声明为普通 def 的处理函数就是被放到线程池执行的。

## 常见错误

忘记 await 导致协程从未执行；在 async 函数里调用 time.sleep 阻塞事件循环；多个任务共享同一个可变的同步对象却没有加锁；以及把 asyncio.run 嵌套在已有事件循环里调用。理解这些边界后，asyncio 能显著提升 IO 密集型服务的吞吐能力。
