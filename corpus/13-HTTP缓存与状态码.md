# HTTP 缓存与状态码

HTTP 缓存能显著降低网络请求量和服务器压力，也是前端性能优化中最容易见效的手段之一。理解缓存的关键是区分强缓存和协商缓存，以及几个高频状态码的含义。

## 强缓存

强缓存由 Cache-Control 响应头控制。max-age 指定资源可以被缓存多少秒，在有效期内浏览器直接使用本地副本，不会向服务器发请求。public 表示允许代理服务器缓存，private 表示只允许浏览器缓存，no-cache 表示必须先向服务器验证才能使用缓存，no-store 表示完全不缓存。强缓存命中时看不到网络请求，速度最快。

## 协商缓存

协商缓存需要浏览器带着验证信息向服务器询问资源是否变化。常见的验证方式有两种：ETag 和 If-None-Match 组合，或者 Last-Modified 和 If-Modified-Since 组合。ETag 是资源内容的指纹，服务器收到 If-None-Match 后对比当前资源的 ETag，如果资源没有变化就返回 304 状态码，响应体为空，浏览器继续使用本地缓存。

## 304 状态码

304 表示 Not Modified，资源未修改，通常出现在协商缓存命中时。它不是错误，而是一种优化：服务器告诉浏览器缓存仍然有效，省掉重复传输响应体的开销。开发调试时如果看到接口返回 304 而内容没更新，应该检查 ETag 是否被错误地复用，或者临时禁用缓存再验证。

## 常见状态码

200 表示成功，201 表示资源已创建，202 表示请求已接受但异步处理中，204 表示成功但无返回内容。301 是永久重定向，302 是临时重定向，307 和 308 保留请求方法的重定向。400 表示客户端请求有误，401 未认证，403 无权限，404 资源不存在，409 冲突，422 参数校验失败，429 请求过于频繁。500 表示服务端内部错误，502 网关收到无效响应，503 服务暂不可用，504 网关超时。

## 设计建议

静态资源可以使用带哈希文件名的强缓存加很长的 max-age；HTML 入口文件应使用协商缓存，保证发版后能及时更新。接口返回 202 时通常配合轮询或轮询接口查询任务状态，这与异步任务的设计是配套的。
