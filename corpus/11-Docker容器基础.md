# Docker 容器基础

Docker 把应用及其依赖打包成镜像，再以容器的方式运行。镜像是一个只读模板，容器是镜像的运行实例。这样做的好处是开发、测试、生产环境一致，不会出现「在我机器上能跑」的问题。

## 镜像分层

Dockerfile 的每条指令都会生成一个镜像层，层与层之间是叠加关系。构建时如果某一层没有变化，Docker 会直接复用构建缓存，跳过重新执行。因此要把不常变化的指令放在前面，例如安装系统依赖、安装 Python 依赖，把经常变化的源码复制放在后面。这样改一行业务代码时只需要重建最后一两层。

## 容器与隔离

容器通过 Linux 的命名空间和 cgroup 实现进程、网络、文件系统和资源隔离。容器共享宿主机的内核，启动速度接近普通进程，比虚拟机轻量得多。容器内的文件系统是写时复制的，容器删除后内部改动随之消失，需要持久化的数据应挂载数据卷。

## 多阶段构建

多阶段构建可以在一个 Dockerfile 里使用多个 FROM 阶段，前面的阶段负责编译和安装构建工具，最后一个阶段只复制运行所需的产物。这样可以显著减小最终镜像体积，同时避免把编译器和源码留在生产镜像里。

## 常用命令

docker build 根据 Dockerfile 构建镜像，docker run 启动容器，docker ps 查看运行中的容器，docker logs 查看日志，docker exec 进入容器执行命令，docker images 列出本地镜像。容器要对外提供服务需要做端口映射，把宿主机端口映射到容器内端口。

## 注意事项

镜像中不要写入密钥和密码，应该通过环境变量或外部配置文件注入。数据目录要挂载卷，否则容器重建会丢数据。生产环境要限制容器资源，并配置健康检查，让编排系统能及时发现异常实例。
