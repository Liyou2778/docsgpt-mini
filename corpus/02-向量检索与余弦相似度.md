# 向量检索与余弦相似度

向量检索把文本映射成固定维度的稠密向量，再通过向量之间的距离或夹角衡量语义相似度。与关键词检索不同，向量检索不要求查询和文档共享字面词项，因此能缓解同义词、改写和跨语言表述带来的漏召回问题。

## 余弦相似度

余弦相似度衡量两个向量方向上的接近程度，计算公式是两个向量的点积除以它们模长的乘积。取值范围是负一到一，越接近一表示方向越一致。因为只关心方向不关心长度，文本向量通常先做 L2 归一化，归一化之后两个单位向量的点积就等于余弦相似度，从而把相似度计算简化成一次点积。

## 确定性哈希向量化

在没有预训练模型、也不允许下载 embedding 模型的离线环境里，可以用确定性哈希把文本映射成向量。做法是对文本做分词，把每个词项用哈希函数映射到固定维度中的一个桶，并使用第二个哈希值决定正负号，把词频权重累加到对应桶里，最后做 L2 归一化。

这里的确定性非常关键：不能使用 Python 内置的 hash，因为它对字符串加了随机盐，每次启动进程结果都不同；必须使用 hashlib 中的摘要算法，例如 blake2b 或 sha256，同一个词在任何进程、任何机器上都会落到同一个桶。否则入库时生成的向量和查询时生成的向量不在同一空间，检索结果就会完全不可用。

## 维度与碰撞

哈希向量的维度是一个可调参数，常见取值是 256 到 1024。维度越高，哈希碰撞越少，向量区分能力越强，但内存占用也越大；维度越低，不同词项容易落到同一个桶，产生噪声。为了减轻碰撞影响，使用带符号的哈希让碰撞以抵消为主而不是单调累加。

## 局限

哈希向量只保留词项级别的统计信息，不具备预训练模型那种深层语义能力，同义不同词的情况仍然会漏。它的优势是完全离线、零依赖、结果可复现，非常适合作为 MVP 的第二路召回与 BM25 互补。
